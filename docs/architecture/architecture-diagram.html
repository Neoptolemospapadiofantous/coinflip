High-Level Architecture

The CoinFlip application follows a layered architecture with clear separation of concerns. Data flows from external services (Supabase, Blockchain) through the data layer, into hooks, and finally to components.

Data Flow

Data flows through multiple layers with validation at each step. Realtime updates invalidate the cache, triggering re-renders. 
sequenceDiagram
    participant U as User
    participant C as Component
    participant H as Hook
    participant Q as Query
    participant V as Validator
    participant S as Supabase
    participant RT as Realtime
    participant BC as Blockchain

    rect rgb(40, 44, 52)
    Note over U,S: READ FLOW
    U->>C: View Page
    C->>H: useGames()
    H->>Q: queryAllGames()
    Q->>S: SELECT from games
    S-->>Q: Raw Data
    Q-->>H: Data
    H->>V: parseDbGames()
    V-->>H: Validated[]
    H-->>C: Game[]
    C-->>U: Render
    end

    rect rgb(40, 52, 44)
    Note over U,BC: WRITE FLOW
    U->>C: Create Game
    C->>H: useContract()
    H->>BC: createGame()
    BC-->>H: TX Hash
    H->>Q: createPendingTx()
    Q->>S: INSERT
    end

    rect rgb(52, 44, 40)
    Note over S,C: REALTIME UPDATE
    BC->>S: Indexer writes
    S->>RT: games INSERT
    RT->>H: Callback
    H->>H: Invalidate cache
    H-->>C: Updated data
    end
